# Where each platform gets its version (Flutter desktop)

`pubspec.yaml` → `version: X.Y.Z+B`. `flutter build` exports `FLUTTER_BUILD_NAME=X.Y.Z` and
`FLUTTER_BUILD_NUMBER=B` (plus `FLUTTER_VERSION*` C defines on Windows). Everything below is
either a **derivation** (reads one of those; no edit needed) or a **copy** (must be edited).

| Platform / file | Kind | Notes |
|---|---|---|
| `macos/Runner/Info.plist` `CFBundleShortVersionString` / `CFBundleVersion` | derivation when `$(FLUTTER_BUILD_NAME)` / `$(FLUTTER_BUILD_NUMBER)`; copy if a literal | Template uses the variables via `macos/Flutter/ephemeral/Flutter-Generated.xcconfig`. |
| `macos/Runner/Configs/AppInfo.xcconfig` | usually no version | Holds name / bundle id / copyright. Some projects add `MARKETING_VERSION` here — a copy. |
| `packaging/macos/make_dmg.sh` (or similar) | derivation if it `sed`s pubspec; copy if `VERSION="1.2.0"` | The dmg file name typically embeds it. |
| `windows/runner/Runner.rc` | **copy** (fallback) | `VERSION_AS_NUMBER 1,0,0,0` / `VERSION_AS_STRING "1.0.0"` are only used when the `FLUTTER_VERSION_*` defines are missing, but they are what someone sees when reading the file, and some CI builds do hit the fallback. Keep them in sync. |
| Inno Setup `*.iss` `AppVersion` | derivation if `GetVersionNumbersString(exe)`; copy if `#define AppVersion "1.2.0"` | The exe's file version comes from Runner.rc → FLUTTER_VERSION. |
| WiX `*.wxs` / NSIS `*.nsi` | copy | `Version="…"` / `!define VERSION` literals. |
| `linux/*.desktop` | **not a version** | `Version=1.0` is the Desktop Entry *spec* version. Never bump it. |
| `snap/snapcraft.yaml` `version:` | copy | Some use `version: git`; then nothing to do. |
| Flatpak manifest / `*.metainfo.xml` `<release version="…">` | copy | metainfo releases are a list; add a new entry rather than rewriting the old one. |
| `debian/changelog` | copy (history) | New stanza on top; old ones stay. |
| `CHANGELOG.md` | history + one new heading | Rename `[Unreleased]` or add a heading; never rewrite old entries. |
| `pubspec.lock`, `Podfile.lock`, generated plugin registrants | never edit | Regenerated by tooling. |
| Dart code showing the version in an About / settings page | derivation if it uses `package_info_plus`; copy if a `const appVersion = '…'` | grep `lib/` for the old number. |

## Sanity checks after a bump

- `grep -rn "<old>" . --exclude-dir=build --exclude-dir=.dart_tool --exclude-dir=Pods --exclude-dir=.git | grep -v "\.lock"` — remaining hits should all be history.
- `git diff` should touch pubspec plus copies only; a diff in a lock file means something ran `pub get` — usually harmless, but say so.
- If the repo has tags, `git tag --list 'v*' | sort -V | tail -3` tells you whether the new version is actually newer than the last release.
